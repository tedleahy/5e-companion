High

A per-level field is now presented as a class-wide toggle

mobile-app/components/classes/custom-class-editor/ProgressionStage.tsx:331–341

addSpellcastingAbility is stored per progression level (DraftLevel.addSpellcastingAbility). Previously the toggle lived inside the per-level section, right after the count steppers, so its per-level nature was clear. It has now been hoisted to the top of the stage — directly under the spellcasting-ability picker and above the level map and the "Level N of 20" detail panel — while still binding to currentLevel.addSpellcastingAbility.

The result reads as a single class-wide setting but silently changes value every time you jump to a different level in the map, and it flips whenever a copy/prefill runs. That is confusing and easy to mis-set (edit it thinking it's global, actually only touch level 1).

// Rendered at the top, outside the per-level detail panel, but per-level data:
<ToggleRow
  label="Add spellcasting ability modifier to prepared spells"
  value={currentLevel.addSpellcastingAbility}
  onValueChange={(v) => updateCurrentLevel({ addSpellcastingAbility: v })}
/>

Fix: either move it back into the per-level detail panel (next to ASI / slots, where "Level N" context is visible), or — if it truly is meant to be class-wide — make it write to every level and read a single source of truth. The D1 mock shows one top toggle because it's a static demo; the real data model is per-level, so the mock's placement shouldn't be copied literally.

High

"Copied from level N" toast fires when nothing was copied

ProgressionStage.tsx:252–279 (selectLevel)

On a +1 level advance the toast is shown whenever the target is untouched (hasDefaultSpellcasting(target)), but it never checks whether the source had anything worth copying, nor whether spellcasting is even enabled.

  • NONE mode: the whole spellcasting section is hidden, yet advancing one level still renders the green "Copied from level N / Undo" banner in the detail panel — nothing spell-related exists to copy.
  • STANDARD mode, empty source: stepping from an untouched level to the next shows "Copied from level N" although both rows are identical and nothing changed.
if (!locked && nextLevel === progressionLevel + 1) {
  const target = draft.progression[nextLevel - 1]!;
  if (hasDefaultSpellcasting(target)) {          // no check on source / mode
    ...
    setCopyToast({ fromLevel: progressionLevel, snapshot });
  }
}

Fix: gate the toast (and arguably the prefill) on showSpellcasting && !hasDefaultSpellcasting(source) so it only announces a copy when something meaningful actually moved.

Medium

ToggleRow puts two "switch" nodes in the accessibility tree

ProgressionStage.tsx:81–99 (ToggleRow)

The row is a Pressable with accessibilityRole="switch" that also renders a Paper <Switch> — which is itself an accessible switch. Screen readers will encounter the row as a switch and the inner control as a second switch, producing a duplicate/confusing announcement. pointerEvents="none" only stops touches, not accessibility focus.

Fix: hide the inner control from a11y — importantForAccessibility="no-hide-descendants" (Android) / accessibilityElementsHidden (iOS), or simply accessible={false} on the <Switch>.

Medium

Overview grid cell widths sum to exactly 100%

ProgressionStage.tsx:542–545 (ovCell) 
width: '18.5%',
marginHorizontal: '0.75%',   // 18.5 + 0.75*2 = 20%  ×5 = exactly 100%

Five cells per row consume exactly 100% of the row. With flexWrap, sub-pixel rounding at certain device widths can tip the total over 100% and drop the fifth cell to the next row (4-per-row layout). The D1 mock avoids this by using CSS grid-template-columns: repeat(5, 1fr), which can't overflow.

Fix: leave a little slack (e.g. width 18%, or use a gap-based layout) so the row can't round past 100%.

Medium

Dead != null guard — summary always shows "slots"

ProgressionStage.tsx:123–129 
const slotsSummary = showSpellcasting ? shortSpellSlots(current.spellSlots) : null;
const metaParts = [
  ...
  slotsSummary != null ? `slots ${slotsSummary}` : null,  // never null when spellcasting
  ...
];

shortSpellSlots returns the em-dash '—' (never null) for an empty level, so the != null branch is always taken and the collapsed summary reads "slots —" for levels with no slots. The guard looks like it intends to omit the segment, but that intent is silently defeated.

Fix: gate on hasSpellSlots(current) instead (or have shortSpellSlots return null for empty and keep the guard).
