Custom Class Wizard UX Plan

Multi-session implementation plan for the create/edit custom class bottom-sheet wizard. Start with Review + Progression — those change how the wizard feels more than colour tweaks.

Verdict

The wizard is solid as a night-sheet admin form — tokens, discard gating, and stage structure are in good shape — but it feels more like a data-entry tool than the polished character-creation flow. Biggest gaps: a stub Review step, painful 20-level Progression UX, and uneven guidance/validation.

Colours already fit night BottomSheet forms (gold labels, parchment inputs, crimson CTA). Don’t chase parchment-list styling inside the sheet — keep night-form consistency.

What’s already working

  • Theme fit for BottomSheet forms via fantasyTokens / nightFormStyles
  • Stage title + 1/6, segmented progress, discard-on-dirty, lock banner
  • Keyboard-aware scroll, shared chips/fields, CardRemoveButton
  • Proficiency nested picker with search/filters
  • Silent prefill when advancing progression levels

Implementation sessions

Each session is sized for one focused agent run. Do them in order unless noted. Paste the session prompt into a new agent chat.

1

Rebuild Review stage

Biggest trust win for a 6-stage form.

High impact Files: ReviewStage, EditorChrome, types

Character creation’s review is sectioned with Edit › jump-backs. Custom class Review only shows name, description, hit die/abilities, and feature/spell counts — no proficiencies, equipment, spellcasting, or level table.

  • Sectioned summary for Identity, Proficiencies, Equipment, Progression, Features/Spells
  • Show key stats (hit die, saves, spell mode/ability, counts, ASI levels summary)
  • Tap section header → jump to that stage (pass onJumpToStage from editor)
  • Keep locked-state copy: only descriptive fields will update when mechanics locked
  • Tests for summary content + jump handlers
  • tsc --noEmit in mobile-app; commit only if asked

2

Progression overview + level jump

Biggest time-saver; kill the 20× stepper grind.

High impact Files: ProgressionStage, SpellSlotsEditor, draft

Editing slots/cantrips/known/prepared one level at a time (×20, and ×9 slot cells for casters) is exhausting. Prefill is silent; there’s no overview of what’s set.

  • Level jump UI: chips or compact 1–20 strip (not only −/+ stepper)
  • Read-only progression summary row/table (ASI / slots / known highlights)
  • Visible “Copied from level N” feedback when prefilling on advance
  • Optional stretch: “Fill remaining levels like this level” action
  • Keep locked mechanics disabled; preserve existing spell slot models
  • Tests for jump, prefill messaging, fill-remaining if shipped
