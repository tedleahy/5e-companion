Character list UI plan

Build the character list mockup in the Expo app against GET /api/v1/characters, at phone, tablet portrait, tablet landscape and desktop widths. Each numbered step is sized for one agent to build and one person to review in a single sitting. The steps run in order, and a step starts only once the one before it is approved.

Definition of done

0Ground rules and decisions

Read this before any step. It applies to all of them.

Current state

  • GET /api/v1/characters is built and tested. Its contract is in the API plan: characters, then drafts as a union of creation and level_up, with q and sort=level|name.
  • The app loads Space Grotesk, derives colour tokens in src/theme/colors.ts, and has useBreakpoint() returning phone, tablet (720 and up) or desktop (1280 and up).
  • src/screens/characters.tsx is a placeholder and src/app/index.tsx routes to it.
  • The mockup draws phone (390), tablet portrait (820), tablet landscape (1180) and desktop (1440). It has no loading, empty or error frames yet.

Rules for every step

  • Follow AGENTS.md. The rules that matter most here:
    • Build from React Native primitives styled with @/theme.
    • Never put a raw hex value in a style.
    • Pick font weight with fontFamily.
    • Use useBreakpoint() for layout that depends on window width.
    • Only routes go in src/app/.
    • Separate adjacent assertions in tests with blank lines.
  • UI copy is American English and sentence case. This plan and the design system are British English, because players never see them.
  • Run shell tools through env mise exec --. Finish every front-end step with npm run lint, npm run typecheck and npm test, all passing. Finish every backend step with bin/rails test and bin/rubocop.
  • Keep each step inside its own scope. If a step needs something from a later one, stop and say so rather than pulling that work forward.
  • Leave the step as a short series of conventional commits on feature/character-list-ui, for example feat(frontend): …. From step 7 on, the reviewer also gets screenshots of the app next to the matching mockup frames.

Decisions already made

TopicDecision
Source of truthThe mockup wins where it and design-system.html disagree. The mockup is newer and matches the API. It has no armour class ring, no marks, no filter chips and no desktop table. Every token is filled with structural ink, the draft tray sits above the list, and Create is the system's rose primary: accent fill, onAccent text and a 5px structural shadow, as on the sheet. Colour values still come from @/theme. The mockup's grid dots and lines are a little fainter than the theme's dot and line tokens; use the tokens.
SortOne button. Each tap switches between level and name, and the label reads "Sort: level" or "Sort: name". There is no menu.
NavigationCard taps, Open sheet, Resume and Create character render with full press and focus states but do nothing. Each takes an optional onPress prop that the screen leaves unset, so a later plan only has to pass handlers. They are not styled as disabled. Try again in the error state does work, because it stays on this screen. Card taps and Open sheet are links, and a handler alone won't do for them: React Native Web leaves Enter on the link role to the browser, which only acts on a real anchor, so a keyboard can't open them. The navigation plan gives them an href instead, for example through expo-router's Link asChild.
FetchingTanStack Query v5, which is pure JavaScript and runs in Expo Go. Search is sent as q after a 250 ms debounce. Stale requests are cancelled through the query's AbortSignal, and the previous list stays on screen while a new search loads.
AuthThe development bearer token comes from EXPO_PUBLIC_API_TOKEN in the git-ignored frontend/.env. There is no login screen. The token is in the bundle, so it is for local development only.
Running on a phoneThe app runs on this computer and is opened over Tailscale, possibly from another network, both in Expo Go and in the phone's browser. Rails listens on the Tailscale address, and development CORS and hosts allow Tailscale IPs and .ts.net names. Nothing listens on the LAN. See steps 3 and 4.
Graphicsreact-native-svg, which Expo Go includes, draws the paper grid, the search icon, the fade behind the sticky footer and the loading spinner. The spinner is custom rather than ActivityIndicator, which draws a different native spinner on each platform and takes only a colour. Offset shadows use the boxShadow style string, which React Native 0.86 and react-native-web both support. Do not add expo-linear-gradient or a shadow library.
Two columnsTablet landscape lays cards out in two columns. Add a fourth breakpoint at 1024 to useBreakpoint() rather than checking the width in the screen.
Hit point meterTen segments. The filled count is the fraction times ten, rounded to the nearest whole, then held between 1 and 9 while hit points are above 0 and below the maximum. That rule reproduces every row in the mockup. The meter shows as hurt when current times two is less than maximum. Temporary hit points only appear in the text line. At 0 the meter is empty. With no current or maximum, or a maximum of 0, there is no meter and the line reads "Hit points not set". The dying, stable and dead states need death save data the API does not return, so they are out of scope.
Draft copyThe API has no pronouns, so draft copy is neutral: "Nothing changes on the sheet until you confirm" replaces "Her sheet is untouched". A creation draft with no name shows "New character". On tablet and desktop, the Resume button reads "Resume level-up" or "Resume creation"; on phone it reads "Resume". Step 1 settles the exact copy for creation drafts.
Subtitle casingThe front end lowercases class names, which are common nouns, and shows subclass names exactly as stored. Step 3 changes the seed data to sentence case, because code cannot tell a proper noun from an ordinary word.
Incomplete charactersA subtitle leaves out a missing race or class, and capitalises the class when the race is missing. With neither, it reads "Race and class not set". A character with no classes has a total level of 0, and its level block shows a dash in dim instead of the number.
List renderingA ScrollView with mapped cards, not a FlatList. A player has tens of characters at most, and the tray spanning both landscape columns is simpler this way.

Out of scope

  • Any navigation, including the character sheet, draft flows, creation and login.
  • Zero hit point states, token colour, marks, the armour class ring and filter chips on the list.
  • Pull to refresh, offline caching, hover states (deferred in the design system), and refetching when the app returns to the foreground.

3Backend: CORS, Tailscale and seed casing

The web build can call the API from this computer and from a phone on the tailnet, and the demo data reads the way the mockup does.

Touches
backend/ only
Depends on
Nothing in this plan
Review focus
That the CORS origins and extra hosts apply only in development, and that nothing listens beyond localhost and the tailnet.

The app is run on this computer and opened on a phone over Tailscale, possibly from another network, both in Expo Go and in the phone's browser. CORS only matters for the browser: Expo Go's native fetch ignores it. The listening address and the host allow-list matter for both.

  • Uncomment rack-cors in the Gemfile. In config/initializers/cors.rb, allow GET on /api/* with the Authorization header, only in development, from these origins on any port:
    • http://localhost and http://127.0.0.1, for a browser on this computer.
    • Tailscale addresses, 100.64.0.0/10, over http, for the phone's browser using the machine's IP. Check with IPAddr; don't write a regular expression for the range.
    • Tailscale MagicDNS names, any host ending in .ts.net, over http or https.
    The API plan deferred CORS until a browser front end existed, and the Expo web build is one. Add no production origin; that belongs with deployment. Anyone on the tailnet can load the page, but the tailnet is only your own devices, and the known token was already development-only.
  • In config/environments/development.rb, add config.hosts << ".ts.net". Development already allows any IP address, but it rejects MagicDNS names.
  • rails server listens on 127.0.0.1 in development, so the phone cannot reach it. Don't change the default to 0.0.0.0, which would expose the demo token to whatever Wi-Fi the computer is on. Document bin/dev -b "$(tailscale ip -4)" in backend/README.md instead, which listens on the Tailscale address only. A browser on the same computer can use that address too.
  • Add a request test. Origins on localhost, on a Tailscale IP and on a .ts.net name get the CORS headers. A LAN address such as http://192.168.1.20:8081 and a public origin don't. The test environment will need the same origins, or the test should set up the configuration itself; pick whichever keeps production untouched.
  • Change the seed data to sentence case: "Life domain", "the Fiend", "Arcane trickster", "Oath of devotion". Check that the seed test still passes and that reseeding updates existing rows.

That the types match the API contract, and the error, cancellation and debounce behaviour.
  • npx expo install @tanstack/react-query react-native-svg. The SVG package is first used in step 6, but installing both now keeps dependency changes in one review.
  • src/api/client.ts: apiFetch<T>(path, { query, signal }). It builds the URL from EXPO_PUBLIC_API_URL, encoding query values, and sends Accept: application/json and Authorization: Bearer ${EXPO_PUBLIC_API_TOKEN}. A response that isn't 2xx throws an ApiError carrying status, and code and message from the API's { error: { code, message } } body. Network failures and aborts propagate unchanged.
  • src/api/characters.ts:
    • The types CharacterSummary, CreationDraft, LevelUpDraft, Draft, CharacterList and CharacterSort = 'level' | 'name', written to the contract in the API plan with nullable fields marked nullable.
    • fetchCharacterList({ q, sort }, signal).
    • A characterListQueryKey helper.
    Add no runtime schema library.
  • src/api/query-client.ts: a factory for a QueryClient that does not retry a 4xx ApiError and retries anything else at most twice. Wrap the stack in QueryClientProvider in src/app/_layout.tsx.
  • src/hooks/use-debounced-value.ts: a generic debounce hook.
  • src/hooks/use-character-list.ts: trims the search text, debounces it by 250 ms, and sends a blank search as no q. Calls useQuery with placeholderData: keepPreviousData and passes the query's signal to the fetch. Returns the query result plus isSearching, which is true while placeholder data shows and a fetch is running.
  • Add EXPO_PUBLIC_API_TOKEN to .env.example, with a comment that it is the local demo token and that the bundle exposes it.
  • Add a "Running on your phone over Tailscale" section to frontend/README.md. It should cover:
    • Start Rails on the Tailscale address, as in step 3.
    • Set EXPO_PUBLIC_API_URL to http://<Tailscale IP or MagicDNS name>:3000. The value is built into the bundle, and localhost on a phone means the phone itself.
    • Start Metro with REACT_NATIVE_PACKAGER_HOSTNAME=<same address> npx expo start. Expo Go otherwise gets the LAN IP, which doesn't work from another network. --tunnel isn't needed.
    • In the phone's browser, open the same address on Metro's port.
    • Use plain http. The tunnel is already encrypted. If the web build is opened over https, for example through tailscale serve, the API must be served over https too, or the browser blocks the requests as mixed content.
    Replace the README's existing advice to use the LAN address.
  • Add a test helper outside src/app/, for example src/test-utils/render-with-query.tsx. It gives each test a fresh client with retries off.

Tests

  • The client builds the URL, encodes q, sends both headers, parses the API error shape, and tolerates an error body that isn't JSON.
  • With fake timers, the hook sends one request after typing stops, not one per keystroke. It sends sort, sends no q for whitespace, keeps the previous data while a new search loads, and aborts a stale request.
  • The query client does not retry a 401.

HelperBehaviour
initial(name)First grapheme cluster, uppercased, so combining accents and joined emoji stay together. Trim surrounding whitespace. A null, empty or whitespace-only name returns an empty string, giving an unnamed draft an empty token. Derive the initial from the actual name, never the fallback title "New character". Use unicode-segmenter/grapheme, a small pure JavaScript dependency that works in Expo Go, because Hermes lacks Intl.Segmenter. Use the same implementation on web and native, without a global polyfill.
subtitle(character)Uses the subrace name, else the race name. Class names are lowercased. One class reads "Mountain dwarf fighter, Champion". More than one reads "Rock gnome wizard 5 / rogue 2, Divination", with each subclass that is present joined by ", " in class order. Missing parts are left out, and the first letter is capitalised if the ancestry is missing. With no ancestry and no classes it returns "Race and class not set".
hitPoints(hp)Always returns display data with a meter and a line. The available meter holds the filled segment count and hurt; the line holds the bold current value and the rest ("/72 hit points", then ", 5 temporary" when temporary is above 0). When unavailable, the meter and bold current value are null and the rest reads "Hit points not set". Clamp the meter, preserving the actual current value in the text, even above the maximum. Follows the rules in step 0.
getNumberWord(n), privateLowercase "zero" to "ten", then digits. Only draftCopy uses it and handles sentence capitalisation.
Next-step lookup, privateA lookup table maps choose_class to "choosing a class" and ability_score_or_feat to "an ability increase or a feat". Any other value drops the Next up sentence rather than showing a raw key. No exported nextStepPhrase function is needed.
draftCopy(draft, compact)Title, detail and resume label for either draft kind. compact selects the phone copy, which omits the next step. Wide copy adds "new character" to a named creation title, but leaves an unnamed title as "New character". Uses the approved copy from step 1; use "choice" when the total is one.

Tests

One test for each row of the mockup, reproducing its subtitle, segment count, hurt state and hit point line. Add edge cases: no classes, no ancestry, null and zero hit points, current above the maximum, 1 hit point, the maximum minus one, an unknown next_step, an unnamed creation draft. Cover combining accents and joined emoji, both sizes of draft copy, zero, ten and larger choice counts, and the singular "choice".
