Principles

What the character list and character sheet mockups are doing, stated so later screens can do the same thing.

Two inks, one paper
  • Structural blue does the work: plates, borders, primary numbers, text.
  • Accent rose is the second pass: offset shadows, the hurt state, and the primary call to action on each screen or sheet.
  • Purple is the overprint. Use it sparingly for concentration-type marks.
Print, not glass
  • Hard offset shadows in flat accent ink. No blur, no gradients on components.
  • Square corners on rectangles. Circles for tokens and the armour class ring.
  • The paper is textured with a dot and line grid so cards sit on something.
Built for play
  • Status is readable at a glance: the filled meter, and on the sheet a mark or two. Token colour is identity, not status.
  • Below half hit points changes the meter colour. The player should not need to read the number.
  • Dense is fine, unscannable is not. Every row has the same shape.
Avoid
  • Rounded corners on cards, buttons or chips.
  • Soft drop shadows, glows, glassmorphism.
  • Introducing green, amber or red for status. Hurt is rose, fine is the token colour.
  • Adding a sixth colour. Derive it from the five inks instead.
  • Raw hex values, or opacity on text, in component styles. Use a token, so a new ink set, including a future dark one, needs no component changes.

Paper surface

The page background is paper with a printed grid: structural dots on a 9px pitch, accent lines on a 27px pitch. It is the only decorative texture in the system, and it stays behind everything.

paper + grid 
background:
  radial-gradient(var(--dot) 1.1px, transparent 1.1px) 0 0 / 9px 9px,
  linear-gradient(var(--line) 1px, transparent 1px) 0 0 / 100% 27px,
  linear-gradient(90deg, var(--line) 1px, transparent 1px) 0 0 / 27px 100%,
  var(--paper);

Cards use plain --card with no texture, which is what makes them read as stuck on. The sticky footer fades from transparent to paper so the grid is visible above the button.

RuleDetail
TrackingTitles and names are tracked tight (-.02em to -.03em). Small labels, such as “Level” and “Waiting to be finished”, are tracked .09em, because they are set in capitals. Nothing else is tracked.
Weights700 for titles, names, numbers, buttons and small labels. 600 for chips and marks. 500 for the hit point line and status lines. 400 for input text and subtitles. 700 is the cap: Space Grotesk has no heavier face, and React Native will not fake one.
CaseSentence case everywhere, including buttons, column headers and the names of features, feats, subclasses, invocations, spells and items: Dark One’s own luck, Pact of the blade, Ring of spell storing. Proper nouns keep their capitals, as in Hunger of Hadar or the Dark One. Two exceptions are set in capitals: the “AC” ring label, and small labels. Small labels are capitals by style only. Their copy is written in sentence case and uppercased in the stylesheet, so copy changes and screen readers still see sentence case.
PersonSecond person for the player: “until you confirm”, “set by you”. The character is called by name or not referred to at all, never by a pronoun, because the app stores no pronouns: “Nothing changes on the sheet until you confirm”, not “Her sheet is untouched”. Quoted rules text stays as printed, even where it says “you”. The sheet mockup’s pronoun copy predates this rule and is due for a rewrite.
SpellingAmerican spelling in the app, so labels match the catalog’s names: armor class, color, gray. This document and the plan stay in British English, because players never see them.
NumbersThe current value is the bold one. Maximums and units stay in dim at regular weight.
OpacityNever lower the opacity of text. Hierarchy comes from size, weight and the dim token, which is contrast-checked. Opacity on top of it is not.

RuleDetail
ResolutionTen segments. The filled count is the fraction times ten, rounded to the nearest whole, then held between 1 and 9 while hit points are above 0 and below the maximum. So 1 hit point still shows one segment, and a scratch still shows one empty. That rule reproduces every row in the list mockup.
Hurt thresholdThe client derives this state when current hit points times two is less than maximum hit points. It is unavailable when either value is null or maximum is zero. The API does not return a below-half flag. This mockup uses data-hurt for the derived state. When hurt, the bold number in the line turns --accent-text as well.
Temporary hit pointsOn the character list, shown in the line only (“5 temporary”), not on the meter. On the character sheet’s tall header, a solid overprint block follows the meter after a gap, and the line still states the amount. It is one block with no empty segments, because temporary hit points have no maximum. The compact header spells it out as “+5 temp”, so colour never carries it alone.
Hit point lineBold current value in structural, or --accent-text when hurt, and the rest in dim at 500. On the list the only note is temporary hit points: “31/44 hit points, 5 temporary”.
Not setWith no current or maximum, or a maximum of 0, there is no meter and the line reads “Hit points not set”, moved up to where the meter was.
ZeroAt 0 the list shows all ten segments empty and the 0 in hurt ink, because its API returns no death saves. The sheet tells dying, stable and dead apart; see zero hit points.
ContrastRose segments reach only 2.5:1 on paper, below the 3:1 target for graphics. That is acceptable only because the hit point line always states the value. Never show a meter without its line.

Decisions

Settled from 11 September 2026 onwards. Each entry carries its date; those without one are from 11 September.

  • Contrast. Text tokens are contrast-targeted in the derivation. Dim and rose text are darker, rose surfaces carry dark text, the inactive chip tint is lighter, and text never uses opacity.
  • Interaction states. Pressed sinks, focus outlines, selected inverts and disabled loses its ink. Hover is deferred.
  • Meter colour. Meters are structural for every character and turn rose below half. The unused alias that suggested token-coloured meters is gone.
  • Token colour. Stored per character as a hex colour. The token is the picker: tap it to change the fill. The letter is contrast-targeted against that fill. Theme inks stay chrome. 16 September 2026.
  • Zero hit points. Dying shows death save pips, stable shows an empty meter, and dead drops the token's ink.
  • Icons. Outline only, 1.8 stroke on a 16 grid, colour from context.
  • Font weights. Capped at 700, the heaviest face Space Grotesk has. 12 September 2026.
  • Font scaling. Body text scales with the operating system setting; fixed circles cap at 1.3 times. First proposal, 12 September 2026.
  • Safe areas and press feedback. The plate paints under the status bar, the Create button clears the home indicator, and Android's ripple is off. 12 September 2026.
  • Hit areas. At least 44 by 44 for every control: an invisible extension on web, hit slop on native. Neighbours meet mid-gap, with a floor of 24. 12 September 2026.
  • Primary buttons. "Only one primary per screen" becomes at most one full-width primary per screen or sheet, with repeated cards and rows allowed one small primary each for their own action. The character sheet designs settled it. 13 September 2026.
  • Selection and semantics. Selected state lives in ARIA attributes, not a data attribute: aria-selected for tabs, aria-checked for single choices including filter chips, and aria-pressed for multi-select toggles. Arrow keys move a choice with roving focus. A list card is one link stretched over the card. 14 September 2026.
  • Case and person. Names of features, feats, subclasses, invocations, spells and items are sentence case, keeping proper nouns. UI copy addresses the player as “you” and refers to the character in the third person; quoted rules text is left as printed. 14 September 2026.
  • Spelling. The app’s UI copy uses American spelling to match the catalog. Internal documents stay British. 14 September 2026.
  • Draft contrast. Dim and rose text are checked against the draft tint over paper as well as over the card colour, because a draft sits on paper and its tint is see-through. Both come out a step darker than before. 14 September 2026.
  • Sheet navigation. A persistent header, tall and compact, with the tabs attached underneath. Detail screens are full-screen pushes, never bottom sheets or in-place expansions; the static bottom sheet is the system's one overlay shape, for the sheet menu, the status picker and the in-play pads. 12 and 13 September 2026.
  • Motion. Two exceptions to instant state changes: the header shrinks continuously as the page scrolls, and the dice roll animates for about half a second, stepped between fixed poses with its shadow held still. Reduced motion shows the result at once. 13 September 2026.
  • Bottom sheets are modal. A scrim in --scrim dims the page, which is inert; focus cycles inside the sheet; Escape, Close or a tap on the scrim closes it and returns focus to the opener, which carries aria-haspopup="dialog" and aria-expanded. No drag, no slide, no grab handle. 13 and 14 September 2026.
  • Editing. Persistent facts sit behind a per-section Edit; an open block takes the draft skin (dashed border, --draft-fill, no shadow) with Cancel and Save, "Was" marks on changed values, and knock-on effects spelled out. List removals are staged until Save; every Add opens its own screen and commits from its footer. 13 September 2026.
  • Destructive button. Outlined in --accent-text, no shadow, never the primary look, used for anything that removes something or ends in death. 13 September 2026.
  • The list redesign.   • Level block and sort. Level moves off the token into its own block, with a dim dash when a character has no classes. Sort is one button that switches between level and name, with no menu. 25 September 2026.

  • Wrapping. Names and subtitles wrap and never truncate, on every card and row. 25 September 2026.

Deferred

Deliberately left until a screen needs them.

  • Hover. Desktop needs some pointer feedback. It should stay within the print metaphor and must not move layout.
  • Empty states. The list’s are designed; see list states. Design the rest with their screens.
  • Zero hit points on the list. Dying, stable and dead need death saves in the list’s API. Until then a list card at 0 shows an empty meter.
  • Sheet copy. The sheet mockup still uses she and her, which the no pronouns rule retires. The specimens here are already neutral. Text a player writes, such as an appearance note, is theirs and stays as written.
  • Dark mode. The derivation should handle a dark paper, but no dark pairing has been tried. Stored token hexes do not remap with the theme.
  • Level-up wizard. The Character tab has its entry and the draft card; the flow itself is its own screen set.
  • Edit conflicts. lock_version catches a change made from another device while a section is open. Nothing shows what happens then.
  • Desktop and tablet sheets. The character sheet is designed at 390 only. The desktop and tablet layouts, and how its pushed screens and bottom sheets behave there, are not drawn.
