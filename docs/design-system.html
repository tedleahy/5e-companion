Distilled from character-list-final.html. It records the "riso" direction: two-ink risograph printing on toned paper, with a third overprint colour where the inks would overlap. Everything on this page is rendered with the same CSS as the mockup, so the specimens are the source of truth, not the prose.

Principles

What the character list mockup is doing, stated so later screens can do the same thing.

Two inks, one paper
  • Structural blue does the work: plates, borders, primary numbers, text.
  • Accent rose is the second pass: offset shadows, the hurt state, and the primary call to action on each screen or sheet.
  • Purple is the overprint. Use it sparingly as a third token colour and for concentration-type marks.
Print, not glass
  • Hard offset shadows in flat accent ink. No blur, no gradients on components.
  • Square corners on rectangles. Circles for tokens and the armour class ring.
  • The paper is textured with a dot and line grid so cards sit on something.
Built for play
  • Status is readable at a glance: filled meter, a mark or two. Token colour is identity, not status.
  • Below half hit points changes the meter colour. The player should not need to read the number.
  • Dense is fine, unscannable is not. Every row has the same shape.
Avoid
  • Rounded corners on cards, buttons or chips.
  • Soft drop shadows, glows, glassmorphism.
  • Introducing green, amber or red for status. Hurt is rose, fine is the token colour.
  • Adding a sixth colour. Derive it from the five inks instead.
  • Raw hex values, or opacity on text, in component styles. Use a token, so a new ink set, including a future dark one, needs no component changes.

Derived tokens

Formulas are in the mockup's derive() function. Text colours come from mixing structural ink toward near-black, secondary text mixes ink toward paper, and every translucent tint is an alpha of one of the inks. Every token that carries text is contrast-targeted. The derivation steps through mix ratios and keeps the first one that reaches 4.5:1 on every surface the text sits on, so the mixer cannot produce a failing palette whatever inks are chosen.

Paper surface

The page background is paper with a printed grid: structural dots on a 9px pitch, accent lines on a 27px pitch. It is the only decorative texture in the system, and it stays behind everything.

paper + grid 
background:
  radial-gradient(var(--dot) 1.1px, transparent 1.1px) 0 0 / 9px 9px,
  linear-gradient(var(--line) 1px, transparent 1px) 0 0 / 100% 27px,
  linear-gradient(90deg, var(--line) 1px, transparent 1px) 0 0 / 27px 100%,
  var(--paper);

Cards use plain --sheet with no texture, which is what makes them read as stuck on. The sticky footer fades from transparent to paper so the grid is visible above the button.

TrackingTitles and names are tracked tight (-.02em to -.03em). Nothing else is tracked.
Weights700 for titles, names, numbers, buttons. 600 for chips and marks. 500 for the hit point line. 400 for input text and subtitles. 700 is the cap: Space Grotesk has no heavier face, and React Native will not fake one.
CaseSentence case everywhere, including buttons, column headers and the names of features, feats, subclasses, invocations, spells and items: Dark One’s own luck, Pact of the blade, Ring of spell storing. PersonSecond person for the player and third person for the character: “until you confirm”, “set by you”, “when she drops a foe”. Quoted rules text stays as printed, even where it says “you”.

OpacityNever lower the opacity of text. Hierarchy comes from size, weight and the dim token, which is contrast-checked. Opacity on top of it is not.

Interaction states

States follow the print metaphor. Pressed things sink onto the paper, selected things invert, disabled things lose their ink. Nothing fades, glows or animates. Every change is instant, so reduced motion needs no special case.

Zero hit points

At 0 hit points a character is dying, stable or dead. Each state changes what sits in the meter slot and adds a bad mark, so it reads without relying on colour. React Native

The app ships as React Native on web, Android and iOS. This page stays HTML because it is the quickest way to iterate on the look, and the web build is a real target. Everything above is platform-neutral: tokens, sizes, anatomy, state rules and contrast. The CSS that renders it is not. This section maps each web technique onto its native equivalent, and records the decisions that only native forces.

Mapping

HereIn React Native
Tokens as custom propertiesA theme object in TypeScript. The derivation is already plain JavaScript with no browser calls, so it ports unchanged. Once code exists, that module is the source of truth and this page mirrors it.
Pixel sizesDensity-independent points. The same numbers carry over.
Cascade and descendant selectorsExplicit props. The riso skin becomes a style factory that takes the theme; there is no inheritance except for text inside text.
Grid columns on rows and the tableFlexbox. Fixed-width views for the token and action columns, flex 1 for the identity column. React Native has no grid.

Inset rings on the level badge, draft token and disabled controlsA border, or an inset box shadow where available. Inset shadows need Android 10 or later.
Dashed rule above the trayReact Native has no per-side border style, so the rule needs its own view or an SVG line. Dashed card borders are fine, because all four sides match.

Decisions native forces

TopicDecision
Font weights700 is the cap, applied here in v0.3. Space Grotesk has no heavier face. A browser quietly substitutes 700 for the 800 the mockup asked for; Android picks a face by family name and will not synthesise one. Bundle 400, 500, 600 and 700 as separate files.
Font scalingText grows with the operating system's text size setting. Names, subtitles, hit point lines, marks and button labels scale freely, and cards grow taller to fit. The token initial, level badge digit, armour ring number and ring label are capped at 1.3 times, because their circles are fixed geometry. This is a proposal: check it at the largest setting before signing off the character sheet.
Safe areasThe plate paints under the status bar, with its content inset below it. The sticky Create button is inset above the home indicator. Desktop is unaffected.
Press feedbackTurn off Android's ripple. The sink is the feedback, on every platform.

Decisions

Settled on 11 September 2026, before designing the next screen.

  • Contrast. Text tokens are contrast-targeted in the derivation. Dim and rose text are darker, rose surfaces carry dark text, the inactive chip tint is lighter, and text never uses opacity.
  • Interaction states. Pressed sinks, focus outlines, selected inverts and disabled loses its ink. Hover is deferred.
  • Meter colour. Meters are structural for every character and turn rose below half. The unused alias that suggested token-coloured meters is gone.
  • Token colour. Stored per character as an ink role and picked at creation. The data model and creation flow now include it.
  • Zero hit points. Dying shows death save pips, stable shows an empty meter, and dead drops the token's ink. First proposal.
  • Icons. Outline only, 1.8 stroke on a 16 grid, colour from context.
  • Font weights. Capped at 700, the heaviest face Space Grotesk has. 12 September 2026.
  • Font scaling. Body text scales with the operating system setting; fixed circles cap at 1.3 times. First proposal, 12 September 2026.
  • Safe areas and press feedback. The plate paints under the status bar, the Create button clears the home indicator, and Android's ripple is off. 12 September 2026.
  • Hit areas. At least 44 by 44 for every control: an invisible extension on web, hit slop on native. Neighbours meet mid-gap, with a floor of 24. 12 September 2026.
  • Primary buttons. "Only one primary per screen" becomes at most one full-width primary per screen or sheet, with repeated cards and rows allowed one small primary each for their own action. The character sheet designs settled it. 13 September 2026.
  • Selection and semantics. Selected state lives in ARIA attributes, not a data attribute: aria-selected for tabs, aria-checked for single choices including filter chips, and aria-pressed for multi-select toggles. Arrow keys move a choice with roving focus. A list card is one link stretched over the card. Token colours are named by the theme. 14 September 2026.
  • Case and person. Names of features, feats, subclasses, invocations, spells and items are sentence case, keeping proper nouns. UI copy addresses the player as “you” and refers to the character in the third person; quoted rules text is left as printed. 14 September 2026.
  • Spelling. The app’s UI copy uses American spelling to match the catalog. Internal documents stay British. 14 September 2026.

Deferred

Deliberately left until a screen needs them.

  • Hover. Desktop needs some pointer feedback. It should stay within the print metaphor and must not move layout.
  • Empty states. Design each one with its screen: no characters, no search results, no drafts.
  • Tablet. Nothing exists between 390 and 1440 wide. Decide once two or three screens show what needs to reflow.
  • Dark mode. The token rule keeps this cheap. The derivation should handle a dark paper, but no dark pairing has been tried.
  • Sheet and form controls. Steppers, toggles, other inputs and dialogs will come out of designing the character sheet.
