Compendium · implementation brief

Five coming-soon shelves, one shared collection

This is a plan for a later implementation pass, not the screens themselves. Visual source remains the five root compendium-*-design.html files. Ship browse-only list and in-place detail that match those designs, built on one collection shell, after promoting the fields that today live only in Prisma raw.

Locked decisions

Scope

Browse only

List plus in-place detail for SRD rows and any existing custom rows (ownerUserId null or the caller). No FAB, editors, archive, or dirty-discard.

UI

Shared collection shell

One CompendiumCollection owns search, Include-SRD, an optional filters slot, results bar, empty state, parchment card, and list↔detail swap. Each category supplies row mark/meta and detail body; only some fill the filters slot.

Data

Promote, then seed

Lift design fields out of raw into typed columns and relations. Resolvers never parse raw. The client never receives raw.

Fidelity

Design extras ship

Race↔subrace links, language “ways to learn” and shared-script peers, inherited parent rules on subraces, background suggested characteristics, and “used by N of your characters”.

Do not

  • Build custom CRUD, a crimson FAB, archive confirmations, or editor sheets for these five types.
  • Force Classes, Subclasses, or Spells into the new collection shell. Their search, pagination, and editing flows differ; leave those screens as they are.
  • Add pagination. SRD catalogs here are 1–16 rows.
  • Change character creation to consume the new browse queries. Race options and ASI maps stay as they are until a later pass.
  • Overload availableBackgrounds. That picker type is already used in creation; add new Compendium types instead.
  • Cram subrace ASI onto AbilityBonus’s [raceId, abilityScoreId] primary key. Add a parallel join.

Render-prop sketch

What the shell owns versus what a category owns

{`type CompendiumCollectionItem = {
  value: string;
  name: string;
  isCustom: boolean;
};

type CompendiumCollectionProps<T extends CompendiumCollectionItem> = {
  title: string;
  noun: string;                 // "race" → "Include SRD races", "9 races · A–Z"
  searchPlaceholder: string;
  searchText: string;
  onSearchTextChange: (text: string) => void;
  showSrd: boolean;
  onShowSrdChange: (next: boolean) => void;
  filters?: ReactNode;          // exclusive chips, script select
  items: T[];                   // already filtered by the screen
  selectedValue: string | null;
  onSelectedValueChange: (value: string | null) => void;
  renderMark: (item: T) => ReactNode;
  renderMeta: (item: T) => ReactNode;
  renderRowExtra?: (item: T) => ReactNode;  // race ability pills
  renderDetail: (item: T) => ReactNode;
  emptyTitle: string;
  emptyBody: string;
  loading?: boolean;
};`}
Shared versus category-specific. Do not rebuild search, the SRD toggle, row chrome, results bar, empty seal, or list/detail motion per screen. Fill the filters slot only where a filter changes what you can see: parent-race chips on subraces, type chips plus script select on languages. Races, backgrounds, and feats leave it empty. Row mark, meta copy, and the detail body stay per category.

Schema promotions

One Prisma migration per promotion, then the matching seeder update. The columns and join are independent, so a single catch-all migration would couple five unrelated diffs and make a revert or a sliced GraphQL pass harder than it needs to be. Also write sourceBook: 'SRD' on these seeders where it is currently omitted (no migration — the column already exists). Update docs/data-model.md in the implementation pass, not as part of this brief.

GraphQL

Every new field is behind requireUser. Catalogs are tiny: one unpaginated list query per category returning the full browse payload. Resolve rows by value (srdIndex ?? id).

Usage-count caveat

Language “known by N” is best-effort until creation writes the join

CharacterLanguage is unused at runtime. Creation copies language names into stats.traits.languages and does not persist the join. Count the caller’s characters whose raceId grants the language and/or who already have CharacterLanguage rows. Do not scrape the traits JSON. Document in the feature doc that creation still does not persist the join, so counts reflect racial grants plus any future join rows — not background “choose N” picks.

Race and background counts use Character.raceId / backgroundId (set on create). Subrace counts use subraceId, which create currently leaves null except on the demo seed — still wire the count; expect zeros until creation stores subraces. Feat counts use CharacterFeat.

Design · compendium-races-design.html

Races

Chips. None beyond Include SRD. Size is visible on the row and only splits 2 Small / 7 Medium in the SRD, so a size filter does not earn a chip row.

Row. Initials or emoji mark; name; SRD/Custom pill; meta is size · speed ft · trait count · languages (N fixed + M choices); ability mini-pills on tablet (DEX +2, Human All +1).

Detail. Hero with speed/size seals and “Used by N of your characters” / “N available subraces”; jump chips (Traits, Languages, Life & build, Subraces); lineage ledger (ASI, languages, trait count); trait grid; always-known versus choose-N languages; Age / Size / Alignment; subrace rows navigate to /compendium/subraces?value=.

Search. Name, source, size, languages, trait names.

Design · compendium-subraces-design.html

Subraces

Chips. Parent race: All plus one chip per parent present in the loaded list (Dwarf / Elf / Halfling / Gnome today).

Row. Parent-race sigil, not initials; meta is parent · +N SCORE or “No additional bonus” · “N added traits”.

Detail. Lineage plus diagram (parent inherited bonus → subrace bonus + trait count); added traits; collapsed parent race rules (speed, size, languages, inherited traits). Parent name links to /compendium/races?value=.

Search. Name, parent, source, description, ability label, traits.

Design · compendium-backgrounds-design.html

Backgrounds

Chips. None beyond Include SRD.

Row. Initials mark; meta is skills · tools · “N language(s) of choice”; clamp the summary/feature lead, not the full feature body.

Detail. Grant strip (Skills / Tools / Languages); starting equipment (fixed ◆ list, choice items prefixed “Choose:”); feature card; collapsed suggested characteristics with counts for traits / ideals / bonds / flaws. Equipment is reference-only, same as classes — not written to inventory.

Search. Name, skills, feature, summary, source.

Design · compendium-feats-design.html

Feats

Chips. None beyond Include SRD. The row meta already shows the prerequisite or “Open to all”; a two-bucket filter does not earn a chip row on a one-feat SRD catalog.

Row. Initials mark; meta is the prerequisite sentence or “Open to all”; clamp the first description paragraph.

Detail. Threshold banner (prerequisite summary or “None — open to all”); “What it grants” as lead sentence plus ◆ benefits parsed from - lines; glance aside (source, ownership, used by). Do not persist a new benefit schema — parse display from existing description[].

Search. Name, description, source, prerequisite text.

Design · compendium-languages-design.html

Languages

Chips + select. Type: All / Standard / Exotic. Script <select> of unique scripts (plus Unwritten). The script cartouche is this page’s signature row mark.

Row. Cartouche (Co / Dw / El / ∅); meta is type · script or “Unwritten / unknown”; clamp speakers, else description, else “No typical speakers listed”.

Detail. Type + script pills; About; typical speakers as tokens; ways to learn (races / backgrounds / traits, read-only); “Known by N of your characters”; same-script peers that jump via ?value= or filter the list.

Search. Name, speakers, scripts, description, type.

Implementation order

The numbers are a real sequence: the shell must land once before five screens copy it.

Prisma migration and seeders

Run bun db:migrate -- <short_name> once per promotion, then bun db:generate after the last of the set (or after each, if you are landing GraphQL per category). Suggested names: subrace-ability-bonuses, feat-prerequisites, language-typical-speakers, background-starting-equipment, background-suggested-characteristics. Seed each field in the same change as its migration. sourceBook: 'SRD' is seeder-only.

GraphQL and resolver tests

Types, five list queries, counts. Resolver tests for promotions, owner scoping, and usage counts. Then bun server:codegen and bun app:codegen.

Shared collection and row

Shell, row chrome, results bar, empty seal, exclusive chips helper, tests. No category-specific copy in the shell.

Screens, simplest first

Languages and feats (flat detail), then races and subraces together (cross-navigation), then backgrounds (richest detail). Each route is a thin wrapper.

Hub counts and enable cards

Wire summaries and hrefs. Coming-soon badges disappear because onPress is no longer undefined.

Docs

Update docs/features/compendium.md current behaviour. Drop “coming soon” and first-phase bullets that no longer apply. Note the language usage-count caveat. Update docs/data-model.md for the promoted columns.

Tests

  • Server: seed/promotion field mapping; counts scoped to SRD versus caller-owned custom; usage counts only include the caller’s characters.
  • Shared collection: search, SRD toggle, results bar, empty state, list↔detail, ?value= selection.
  • One screen test per category covering list rows, SRD filter, detail sections, and empty copy. Subraces also cover parent-race chips; languages cover type chips and the script select.
  • Hub: each of the five cards is enabled and shows an SRD/custom summary.
  • Navigation constants include the five new top-level paths.

Run tsc --noEmit in server/ and mobile-app/ before calling the pass done. No production conditionals for tests.
