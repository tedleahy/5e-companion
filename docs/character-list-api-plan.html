Character list API plan

Current state

The repository already has the foundation. Do not regenerate it.

  • Rails runs from backend/ as FiveECompanion.
  • Ruby 4.0.6, Rails 8.1.3.1, and PostgreSQL 18.6 are pinned.
  • compose.yaml and database.yml use the 5e_companion role and database prefix.
  • Users, sessions, characters, classes, resources, features, effects, and drafts have migrations, models, constraints, and fixtures.
  • The development seed creates six demo characters, a second user's character, and Kethra's level-up draft.
  • Bearer authentication sets Current.session and Current.user.
  • A composite foreign key prevents a draft from referencing another user's character.
  • The character-list seed refuses to create or print its known credentials outside development and test.
  • GET /api/v1/characters validates search and sort parameters, returns explicit character summaries, and includes both draft kinds.

The schema is broader than this endpoint because the character sheet needs token ink, armor-class overrides, resources, features, and effects. Keep those tables and columns. The list endpoint must not load or return them.

1Fix the contract

Frontend and backend work against one small, explicit response.

GET /api/v1/characters?q=vesper&sort=level
Authorization: Bearer <development token>

Query parameters

ParameterRules
q Optional scalar string, at most 100 characters. Trim whitespace. Blank means no search. Match names case-insensitively and escape literal %, _, and backslashes before using ILIKE.
sort Optional scalar string. Allow level and name only; default to level.

Reject an array, object, overlong search, or unknown sort with HTTP 400 and this stable shape:

{
  "error": {
    "code": "invalid_query",
    "message": "Unsupported query parameters."
  }
}

Ordering

  • sort=level: total class level descending, case-insensitive name ascending, then ID ascending. A character with no classes has level 0.
  • sort=name: case-insensitive name ascending, then ID ascending.
  • Drafts are independent of character search and sort by most recently updated, then ID descending.

Drafts form a discriminated union. A creation draft reads its provisional name and progress from state; name may be null until the player supplies one. A level-up draft reads its character identity from the associated character and its progress from state. Do not add null level-up fields to creation drafts.

Return IDs as strings and levels, hit points, and progress counts as JSON numbers. Keep classes in their stored position order. Do not add links, count metadata, pagination, token ink, armor class, badges, effects, resources, features, CSS classes, meter segments, formatted summaries, or HTML.

The frontend derives the token initial, ancestry and class summary, HP fraction, and low-HP colour. The API does not return a below-half flag. Low HP means current HP times two is less than maximum HP. It uses the subrace name when present and otherwise uses the race name. An HP meter and low-HP state are unavailable when current HP is null or maximum HP is null or zero. Clamp the displayed fraction to 0 through 1. Temporary HP does not affect the fraction or low-HP state.

2Implement the endpoint

One controller action returns owned characters and both draft kinds.

Protect draft ownership

The data model requires the draft and its character to have the same user_id. Add a follow-up migration because the original migrations are already committed:

add_index :characters, [:user_id, :id], unique: true

remove_foreign_key :character_drafts, :characters
add_foreign_key :character_drafts, :characters,
  column: [:user_id, :character_id],
  primary_key: [:user_id, :id],
  on_delete: :cascade

The composite foreign key permits a null character_id for creation drafts and rejects a level-up draft attached to another user's character. Mirror it with one friendly model validation for API writes.

Keep demo credentials local

Guard backend/db/seeds/character_list.rb before it creates or prints the known password and bearer token:

raise "Character-list demo seeds are local only" unless Rails.env.local?

Rails.env.local? allows development and test, which keeps local setup and CI working without making the known token available in production.

Add the route and controller

# backend/config/routes.rb
namespace :api do
  namespace :v1 do
    resources :characters, only: :index
  end
end

Use Api::V1::CharactersController in backend/app/controllers/api/v1/characters_controller.rb. Replace the current singular, unnamespaced controller draft rather than keeping both.

The action should:

  1. Validate q and sort before building SQL.
  2. Start from Current.user.characters.
  3. Apply escaped name search when q is present.
  4. Sort in PostgreSQL with a fixed allow-list. Never pass a raw sort value to order.
  5. Preload only character_classes for character summaries.
  6. Load Current.user.character_drafts.includes(:character) separately so search does not hide drafts.
  7. Render explicit hashes through private character_summary and draft_summary methods.
render json: {
  characters: characters.map { |character| character_summary(character) },
  drafts: drafts.map { |draft| draft_summary(draft) }
}

Branch on draft.kind inside draft_summary. Return the two shapes from step 1. Raise on an unknown kind; the database constraint should make that path unreachable.

Keep the implementation local

Private controller methods and the existing Character.named scope are enough. Do not add a serializer gem, query object, service layer, pagination, or OpenAPI document for this endpoint.

Add CORS only when a browser frontend runs on another origin. A React Native client does not need it.

3Test the endpoint

A small request suite locks down the public contract and ownership.

Keep endpoint fixtures smaller than the development seed. Request tests assert the fixture-owned count; the seed test alone asserts six demo characters.

Migration and model checks

  • The database rejects a draft whose user does not own its character.
  • A creation draft with no character remains valid.
  • Total level sums ordered class rows and returns 0 for a character with no classes.

Request checks

  • Missing, unknown, and expired bearer tokens return the existing 401 error.
  • The other user's characters and drafts never appear.
  • The happy path returns the exact public keys under characters and drafts. An allow-list assertion is clearer than a blacklist of private columns.
  • Creation and level-up drafts use their agreed, distinct shapes.
  • Search is case-insensitive, trims whitespace, and treats literal %, _, and backslashes safely.
  • A blank search returns the full owned list without hiding drafts.
  • Level and name sorts are deterministic, including tied names and a character with no classes.
  • Unknown sorts, overlong searches, arrays, and objects return the stable 400 error.
  • Character summaries work under strict_loading, proving classes were preloaded. Draft summaries preload their optional character.

Seed checks

  • The local seed is repeatable.
  • The demo user has six characters and Kethra's level-up draft.
  • The second user's character stays separate.
  • The seed refuses to create or print known credentials outside a local environment.

4Connect the frontend

This is a separate follow-up after the API definition of done passes.

  1. Generate the React Native application in frontend/ when its framework choices are ready. Do not create placeholder package or workspace configuration.
  2. Keep the API base URL and development token in an ignored local environment file. A browser bundle cannot keep a bearer token secret; this known token is for local development only.
  3. Replace hard-coded character and draft data with the endpoint response.
  4. Render creation drafts as "Resume creation" and level-up drafts as "Resume level-up". Use "New character" when a creation draft has no provisional name.
  5. Wire search and sort to query parameters. Debounce search by roughly 200 to 300 ms and cancel stale requests.
  6. Render loading, empty, unauthorized, and generic error states.
  7. Compare screenshots at the four mockup layouts: phone, tablet portrait, tablet landscape, and desktop.

Keep mockups/, docs/, and srd-json-files/ at the repository root. Add root development, test, and CI wrappers only after both applications exist and repeating their commands becomes a real nuisance.

Definition of done

API milestone

  • A fresh checkout starts PostgreSQL and prepares Rails with bin/setup.
  • backend/bin/ci passes.
  • The composite draft ownership constraint is present in backend/db/schema.rb.
  • The known demo credentials can be seeded only in development and test.
  • An authenticated request returns owned characters plus creation and level-up drafts.
  • Name search and both sorts satisfy the contract.
  • The endpoint performs no association query per character or draft.
  • The response contains only the documented public fields.

Frontend follow-up

  • The frontend contains no hard-coded character or draft game data.
  • Both draft kinds have resume actions.
  • Loading, empty, unauthorized, and generic error states work.
  • Phone, both tablet layouts, and desktop match the mockup.
